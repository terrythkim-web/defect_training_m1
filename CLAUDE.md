## What the app is

DefectLab: a PySide6 desktop app that takes a few defect example images → BBox/Polygon labeling → offline augmentation → Ultralytics YOLO11 training (detect or seg) → ONNX export. Left side = image list + labeling canvas; right side = tabs `Augment / Train / Result / Compare / Export`. It can also train on cropped regions and compare Full vs Crop models in an HTML report.

## Commands

The venv is `.venv` (Python 3.12, created with uv; system Python is 3.14, which torch may not support). PyTorch must be installed before the package — see README for per-OS CUDA/CPU commands.

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python torch torchvision --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv/bin/python -e ".[dev]"

.venv/bin/python -m defect_inspection.app                      # run the app
.venv/bin/python -m pytest                                      # all tests
.venv/bin/python -m pytest "tests/test_app.py::test_main_window_opens"  # single test
```
`tests/conftest.py` forces `QT_QPA_PLATFORM=offscreen`, so tests run headless.

## Architecture (intended — only `app.py`, `ui/main_window.py`, `platform_utils.py`, `core/project.py`, `core/imaging.py`, `core/annotation.py`, `core/image_cache.py`, `ui/canvas/image_canvas.py`, `ui/image_list.py`, `ui/thumbnails.py`, `ui/label_list.py`, `core/label_edit.py`, `ui/canvas/{session,labeling_canvas,shape_items,tools}.py`, `core/sam_assist.py`, `ui/sam_controller.py`, `core/weights.py`, `core/att_yolo.py`, `core/model_zoo.py`, `core/augment.py`, `core/augment_config.py`, `core/dataset.py`, `core/preview.py`, `ui/panels/augment_panel.py`, `core/trainer.py`, `worker.py`, `ui/train_process.py`, `ui/panels/train_panel.py`, `ui/widgets/training_charts.py`, `core/evaluate.py`, `ui/panels/result_panel.py`, `core/exporter.py`, `ui/panels/export_panel.py`, `core/roi.py`, `ui/canvas/roi_tool.py`, `core/crop.py`, `core/crop_config.py`, `core/compare.py`, `ui/panels/compare_panel.py`, `core/report.py`, `selfcheck.py` exist so far; tools: `tools/bench_apple.py`, `tools/mlx_yolo.py`)

- Right-side tabs are a `ScrollTabs` (vertical-scroll page per panel; `setCurrentWidget`/`currentWidget`/`indexOf`/`widget` map to the panels). Without it the Augment tab made the window's minimum height 893 px, taller than a 13" MacBook's 870 px usable screen. Shape tags use `shape_items.tag_font()` (created after the QApplication; an import-time `QFont` has no family and measured wrong on macOS).
- `MainWindow` owns the `Project`, a shared `QUndoStack`, the current `Tool` (emits `tool_changed`) and `project_changed`; later canvas/panels should hook into these rather than keep their own copies. Tests construct `MainWindow(QSettings(ini_path, IniFormat))` so layout persistence never touches the real user settings.
- `defect_inspection/core/` is Qt-free logic (project model, annotation, augment, crop, trainer, compare, report, exporter); `ui/` holds the main window, canvas tools, and one panel per right-side tab. Keep core testable without a display.
- **Project model** (`core/project.py`): `project.yaml` is a pydantic `ProjectConfig`; a class's index in `classes` is its YOLO class id, so reordering/removing classes requires remapping labels. Image paths are stored relative to `images/` with POSIX separators. Train/Val split is computed on demand (`compute_split`), never stored: manual `split` overrides win, the rest are ranked by seeded SHA-1 of the path — don't switch to `random`/`hash()`, which would break reproducibility across runs and OSes.
- **Color mode** (F1.6): `color_mode: grayscale` stores project images single-channel (bit depth kept, conversion in `core/imaging.to_grayscale`) and `Project.channels` (1 or 3) must flow through every later stage: augmentation (no color transforms), `data.yaml` `channels:`, model input, ONNX input shape and export metadata.
- **Label editing** (step 6): all edits go through `LabelSession` (one per open image), which pushes a before/after snapshot `QUndoCommand` onto `MainWindow.undo_stack`; never mutate `session.annotations.shapes` directly from UI code, or undo breaks. Geometry math lives Qt-free in `core/label_edit.py` (returns new shapes, same id). Canvas `ShapeItem`s only preview during a drag and report on mouse release; the session's `changed` signal rebuilds all items, so the model is the single source of truth. Switching image saves the session (`_close_session`) and clears the undo stack, so history is per image. Scene coordinates == image pixel coordinates (pixmap item at the origin, unscaled).
- **SAM assist** (step 7): `core/sam_assist.py` is Qt-free (prompt → mask → `mask_to_shape`, always `status=suggested, source=sam`). `SamController` runs it on ONE worker thread; requests carry a generation number and `MainWindow._on_sam_result` drops anything not matching `_sam_generation`, the current session, or the SAM tool. The image embedding (~4 s on CPU) is cached per image key and pre-computed when the SAM tool is selected; clicks then take ~0.3–0.6 s. Point prompts for one object must be shaped (1, n, 2) — see `SamPrompt.to_kwargs`. Weights resolve into `<cache>/weights`, never the working directory. Tests swap in a fake via `MainWindow.set_sam_controller`; `tests/test_sam_assist.py::test_real_sam_segments_a_blob` runs only if `~/.cache/DefectLab/weights/mobile_sam.pt` exists.
- **Autosave**: `QTimer` (`autosave/interval_sec`, default 30 s, 0 = off) saves the label session and `project.yaml`; labels are also saved on image switch, Ctrl+S and close.
- **Image display pipeline**: never decode images on the UI thread (a 4K PNG takes ~150 ms). `ImageCache` (Qt-free, thread-safe LRU) holds display-ready uint8 images; `MainWindow` uses `get_async` + a queued signal and drops results for images the user already left, and prefetches list neighbours. `to_display_8bit` (16-bit percentile stretch) and brightness/contrast are display-only — never feed display images into labels, datasets or training. Thumbnails come from `ThumbnailLoader` worker threads with a disk cache keyed by path+mtime+size; `MainWindow(..., cache_root=tmp)` keeps tests out of the user cache.
- **Labels** (`core/annotation.py`): `labels/<image stem>.json` (pixel coords, top-left origin, continuous so a full-image box is (0,0)-(W,H)) is the source of truth; `labels/<stem>.txt` is always *derived* via `Project.save_labels` / `regenerate_yolo_labels` (call the latter after changing `task`). detect → polygon becomes its bounding box; seg → bbox becomes a 4-point polygon; shapes are clipped to the image and dropped if fully outside. Because labels are keyed by stem, `add_images` keeps image stems unique (`a.png` + `a.jpg` → `a_1.jpg`). Shapes carry a stable `id` (for UI selection/undo) and a `class_id` index into `classes`. Auto-label suggestions (F2.8: trained-model predictions and SAM click assist) live in the same JSON with `status: suggested` + `source`/`score`; they are excluded from YOLO txt and training until accepted via `ImageAnnotations.accept`/`accept_above`. Anything that generates labels must add them with `add_suggestions`, never as confirmed shapes.
- **Augmentation** (`core/augment.py`, F3): `Augmenter(config, channels, seed)` runs an Albumentations pipeline built from `AugmentConfig` (per-transform enabled/p/strength; registry `TRANSFORMS`, presets `BUILTIN_PRESETS` + user YAML via `save_preset`/`load_presets`). All shapes (boxes too) travel as polygon keypoints and are shifted −0.5/+0.5 around the transform because Albumentations keypoints use pixel indices (flip = W−1−x) while labels are continuous; removing the shift makes every flipped label 1 px off. After the transform shapes are clipped and dropped below `min_visibility`/`min_area_px`. Only confirmed shapes are augmented; input must be uint8; colour-only transforms are skipped for 1-channel projects. `tests/test_augment.py::test_labels_follow_pixels` rasterizes shapes and checks labels still match the pixels — keep it passing when adding geometric transforms. Albumentations validates parameter ranges (e.g. `Illumination` intensity ≤ 0.2), so new transforms must build at strength 0 and 1.
- **Dataset build** (`core/dataset.py`, F3.2): `build_full_dataset(project, progress, cancel)` → `dataset/full/` (+ `data.yaml` with `channels`, `build_info.yaml`). Includes images with confirmed labels and OK images only (unlabeled / suggestion-only images are skipped on purpose). Split is stratified (defect and OK images separately, `split_images`) and needs ≥1 Val defect image. Pixels go through `imaging.to_training_8bit` (16-bit → `>> 8`, a fixed mapping — NOT the per-image display stretch). Built in `full.building/` and swapped in at the end. Copy-Paste takes patches from Train defect images only and pastes onto Train OK images. Augmentation settings live in `project.yaml` as `augment` (pure-pydantic `core/augment_config.py`, so loading a project never imports Albumentations, ~1 s); `core/augment.py` imports it lazily.
- **Augment tab**: edits write straight into `project.config.augment` (emits `changed` → `mark_dirty`). Preview runs `core/preview.augment_previews` on a worker thread (generation-numbered, downscaled to 480 px with `min_area_px` scaled accordingly) and uses the session's unsaved labels via `annotations_provider`. Build runs `build_full_dataset` on a `QThread`; `before_build` saves labels + project first. Connect worker-done signals to `QThread.quit` with `DirectConnection` — queued, they deadlock when `closeEvent` waits for the build. `MainWindow.load_project` must call `augment_panel.set_project` *before* `_refresh_lists` (which selects the first image).
- **Train tab**: form → `TrainConfig`; model combo comes from `model_zoo.MODEL_CHOICES` (default `yolo11s`, switching applies the model's imgsz/epochs and shows its note). Events from `TrainProcess` drive progress/ETA/log and `TrainingCharts` (fed through `core/trainer.EpochSeries`, which also replays `events.jsonl` for a selected history row and trims overlap after a resume). Charts follow the dataviz skill: two charts (no dual axis), fixed palette order (`SERIES`), loss colour = component and dash = val, legends as a text row above each plot (in-plot legends covered data). The worker's `model` event reports the real input channels; the panel warns if they differ from the project. `MainWindow` blocks project switching during training and asks before closing (then `train_panel.shutdown()`).
- **Result tab** (`core/evaluate.py`): `Predictor` (cached per best.pt + mtime) returns app shapes with `status=suggested, source=model, score`; images go through `to_training_8bit` like training. Val grid predicts once at conf 0.01 and the conf slider re-filters/re-matches without predicting again (greedy, same class, IoU ≥ 0.5). Suggestions (`generate_suggestions`) only touch unlabeled non-OK images and replace earlier `model` suggestions; afterwards `labels_changed` makes `MainWindow` refresh list statuses and reload the open session (otherwise its stale shapes would overwrite the new file). Quick suggest chains Augment build → `train_panel.start(quick_suggest_config())` → `result_panel.suggest(run)` via `_quick_stage`. `AugmentPanel.is_building` is a flag cleared *before* `build_finished`/`build_stopped` fire — follow-up actions in those slots would otherwise see "still building". Tests fake the model with a blob detector (`BlobPredictor`); window fixtures call `train_panel.shutdown()` before `close()` so teardown never hits the blocking "학습 중" dialog.
- **ONNX export** (`core/exporter.py`): `export_run(project, run_dir, out_path, ExportOptions)` → `<name>.onnx` + `<name>.metadata.json` + `<name>.classes.txt` (`sidecar_paths`), default name from `default_export_name(pattern, project, mode, model, now)`. Exports on CPU (FP16 only with CUDA), imgsz defaults to training imgsz, ATT-YOLO forced to a fixed size. `verify_onnx` compares Ultralytics predictions of best.pt vs the .onnx (same pre/post-processing) — every detection same class, IoU ≥ 0.99. ONNX input is RGB (or 1-channel gray); metadata spells out the preprocessing. `YOLO_AUTOINSTALL=false` is set in `defect_inspection/__init__.py` so Ultralytics never pip-installs at run time (`onnxslim` is a declared dependency).
- **Export tab**: name field has a `QRegularExpressionValidator` that refuses forbidden characters as typed; `problem()` checks reserved names and the 260-char limit on the longest of the three output files. While the name is unedited (`_name_edited`), it is regenerated at export time so the timestamp is the export time. Pattern lives in QSettings `export/name_pattern` (Settings menu). Export runs on a plain thread and reports via a queued signal. Tests: `QTest.keyClicks` with Korean text aborts Qt offscreen — set text and emit `textEdited` instead.
- **Crop ROI** (step 16, F7.1): `core/roi.RoiStore` owns `crops.json` (per-image ROIs + `common` ROIs for every image + drawing `options`), written immediately on every change. `RoiStore.effective(image, W, H)` = common ROIs clipped to the image + its own — use it for crop generation. In the UI all ROI edits go through `RoiSession` (snapshot `QUndoCommand` on the shared undo stack, like `LabelSession`). `RoiItem`s sit at z=0.5 below labels and accept mouse buttons only while the tool is `Tool.CROP_ROI`, so other tools click through to labels; fixed-size ROIs are not resizable. `RoiItem` is a QGraphicsItem, not a QObject — no `self.tr`.
- **Crop dataset** (step 17, F7.2–F7.5): `build_crop_dataset(project, progress, cancel)` → `dataset/crop/`, same selection/split helpers as the full build (`select_images`, `split_images`), so an image is on the same side in both datasets. Windows per image come from `plan_windows` (order roi → defect → background → tile, deduplicated) with `image_rng(seed, path)` (SHA-1, reproducible across OSes). Labels go through `crop_annotations`, which uses `annotation.fit_shape` — the same clip + `min_visibility`/`min_area_px` rule the Augmenter uses; keep it shared. Labels entirely outside a window are not counted as dropped. Only Train crops are augmented (`crop.multiplier`, Copy-Paste is not used for crops). Requires ≥1 Val crop with a label. `build_info.yaml` has `window: {size, overlap_px}` for tiling inference / ONNX metadata (steps 18, F6). `CropConfig` is pure pydantic in `core/crop_config.py` (project.yaml `crop`), presets `CROP_PRESETS`. Crop file names: `<stem>__<kind><nnn>[_augNN]`. The Augment tab's build mode combo picks Full/Crop; quick suggest always calls `start_build("full")`.
- **Ultralytics task pitfall**: when loading a `.pt`, Ultralytics takes the task from the model object / checkpoint `train_args`, NOT from `YOLO(path, task=...)`. Checkpoints we save ourselves from YAML-built models (ATT-YOLO init, test fixtures) must set `model.task` and `ckpt["train_args"]["task"]` first, or a seg model reloads as detect. Still pass `task=` everywhere for ONNX files.
- **Models** (F4.1, F4.8): create every training model through `core/model_zoo.make_model` (choices `yolo11n/s/m`, `att-yolo-n/s`; default `yolo11s`). ATT-YOLO (`core/att_yolo.py`) is the paper's P2–P7 six-head design with C3TR self-attention after P7, rebuilt for Ultralytics' anchor-free heads, so there is no auto-anchor. Backbone layers 0–8 match YOLOv5 exactly and get `yolov5{n,s}u.pt` weights via `transfer_backbone`; the result is saved as a checkpoint because Ultralytics re-creates YAML-only models from scratch at `train()`. Two Ultralytics pitfalls are handled there, keep them: (1) loading a YAML file overwrites `scale` with a guess from the file name, so the config uses explicit `depth_multiple`/`width_multiple`; (2) YAML `channels` is ignored by `DetectionModel`, so the model object is rebuilt with `ch=channels`. Weights always resolve through `core/weights.resolve_weights` into `<cache>/weights`.
- **Slow tests**: `@pytest.mark.slow` (real training + ONNX export) are excluded by default (`addopts` in pyproject); run them with `.venv/bin/python -m pytest -m slow`.
- **Training runs in a separate process**: `core/trainer.prepare_run` writes `runs/<id>/config.yaml` (`RunSpec`), then `ui/train_process.TrainProcess` (QProcess) starts `python -u -m defect_inspection.worker --run-dir …` (frozen builds: app exe with `--train-worker`, handled in `app.py`). Events are stdout lines `@@DL {json}` (`start, transfer, train_epoch, epoch, final, done, stopped, error`), also appended to `events.jsonl`; `status.json` holds the state. Stop = write `stop` to stdin → the worker raises `StopTraining` from `on_train_batch_end`, deliberately skipping Ultralytics' final_eval, which would strip the optimizer from `last.pt` and break resume; kill after `STOP_TIMEOUT_MS`. Ultralytics calls `on_fit_epoch_end` again from final_eval — the worker reports that as a `final` event, not an extra epoch. A worker that exits without a final event is recorded as failed (or stopped if a stop was requested). Fast tests use `DEFECTLAB_FAKE_TRAIN="<epochs>:<sec>[:hang]"` (and `DEFECTLAB_FAKE_CRASH`) to exercise the real QProcess path without Ultralytics; real training is `@pytest.mark.slow`.
- **Two datasets coexist**: `dataset/full/` and `dataset/crop/`, each with its own `data.yaml`.
- **Leakage rule (applies everywhere)**: split Train/Val by *original image* first, then crop/augment. Only Train is augmented; Val is never augmented and crops from one source image never span both splits.
- **Crop models on full images** (step 18, F7.6): `TiledPredictor(predictor, TilingParams)` has the `Predictor.predict(image8, conf, iou)` interface, so `evaluate_images`/`generate_suggestions` work unchanged. It uses the dataset's `tile_windows` (last tile flush with the edge), `to_original`, then `merge_predictions` (per class, greedy by score, IoU ≥ 0.5 or IoS ≥ 0.7 — IoS removes pieces cut by a tile border). `TilingParams` (`core/crop_config.py`) is frozen into `RunSpec.crop` by `prepare_run` from `dataset/crop/build_info.yaml`; always ask `spec.tiling()` (None for full runs, fallback for old crop runs). Factories: `evaluate.predictor_for_run(weights, spec)` and `predictor_for_onnx(path)` (reads the metadata). The Result panel builds `Predictor` itself (tests monkeypatch it) and wraps it. `val_images(project, "crop")` maps crop files (`<stem>__…`) back to the original Val images. Use these for the Full-vs-Crop comparison.
- **Fair comparison** (`core/compare.py`, step 19, F8.1–F8.4): `compare_runs(project, run_dirs, conf, iou, make_predictor, devices)` re-evaluates every run on `fair_val_images(project)` — the project's own per-image Val split (defect + OK), NOT a dataset folder listing (a crop dataset may have no crop for an OK image). Predicts once down to conf 0.001 (`ImagePredictions`), then `compute_metrics` derives P/R/F1 at conf (Result-tab `match`), COCO 101-point mAP50/50-95 per class, size-bin recall, OK/NG judgement. Box-based for seg too. Speed = median of 5 images per device from `platform_utils.inference_devices()`; `Predictor(..., device=)` exists for that. `recommend()` implements the F8.5 rule (priority metric, within 1 %p → faster on CPU) — reuse it in the step-20 report. `RunComparison.summary()` is JSON-friendly. Tests inject `make_predictor` (blob fake, `test_compare.blob_factory`) and `devices=[("CPU","cpu")]`. The Full + Crop experiment is a stage machine in `MainWindow` (`_exp_stage`: build_full → build_crop → train_full → train_crop → compare), like quick suggest. `AugmentPanel.start_build` called from a `build_finished` slot is queued (`_pending_build`) until the finished thread is cleaned up — without that the second build was silently dropped.
- **Report** (`core/report.py`, step 20, F8.5/F8.6): HTML only — `build_report(project, results, run_dirs, priority, memo)` writes one self-contained file `reports/<YYYYMMDD_HHMM>_full_vs_crop.html` (`_2`… in the same minute) with Jinja2 (autoescape) + matplotlib Agg figures as base64 PNG and example cases as base64 JPEG. Do not add PDF/Markdown/CSV output. The metrics table comes from `compare.metric_rows` (shared with the Compare tab; change it there). The experiment is embedded as JSON in `<script type="application/json" id="defectlab-data">` (`</` escaped); `list_reports`/`read_report_data` use it for the history and `ReportInfo.configs` for "같은 설정으로 재실험", which calls `MainWindow.start_experiment(configs)` (generic step queue: builds the needed datasets, trains every config, compares). Korean font via `setup_matplotlib()` → `platform_utils.pick_korean_font`; CI installs `fonts-noto-cjk`.
- **Packaging** (`packaging/`): `spec_common.collect` lists what PyInstaller cannot see (ultralytics cfg YAMLs + lazy submodules, albumentations/pyqtgraph/onnxslim submodules, onnxruntime libs, lazily imported `defect_inspection` modules). Windows ships `DefectLab-worker.exe` (console) next to the windowed app; `platform_utils.frozen_worker_command` prefers it, else the app exe runs with `--train-worker`. `app.main` calls `multiprocessing.freeze_support()` first, then `platform_utils.use_persistent_matplotlib_cache()` (PyInstaller's matplotlib runtime hook sets a fresh temp `MPLCONFIGDIR` per start, so every app start and training worker rebuilt the font cache — ~15–20 s on an M1, once stalled for minutes), and handles `--self-check` (`selfcheck.py`) before importing Qt widgets. Build scripts run the frozen `--self-check` (imports, model YAMLs, torchvision NMS, ONNX Runtime, ONNX export, Korean font, main window); `.github/workflows/package.yml` (manual) builds both OSes. Pitfall found by actually training with the Linux bundle: the stock hooks miss torchvision's `_C_stable.so`, and frozen training then dies with "operator torchvision::nms does not exist" — `spec_common.native_libs("torchvision")` adds it; keep the NMS self-check. Verified on Linux (aarch64, CPU torch): self-check + 2-epoch training through `DefectLab --train-worker`. The Windows spec has not been built yet (needs a Windows machine or the Package workflow).
- **Apple tools** (step 22): `tools/mlx_yolo.py` rebuilds a YOLO11 detect network in MLX from an Ultralytics PyTorch model (weights transposed NCHW→NHWC; channel-order-sensitive ops — C2f split, attention view, Detect flatten — written to match PyTorch). It is a benchmark port, not a training engine: no Ultralytics loss/assigner. `tests/test_bench_apple.py` checks outputs (1e-4), loss and gradients (5e-3, float32 over ~100 layers) on the MLX CPU build (`.[bench]`, Linux CI installs it; skipped where MLX is missing). `tools/bench_apple.py` measures raw network inference only (no NMS: an untrained model's NMS dominated) and exports into a temp dir (YAML-built Ultralytics models export into the CWD). CoreML: `ExportOptions.format="coreml"`, gated by `platform_utils.COREML_EXPORT_AVAILABLE` (macOS), colour only, `.mlpackage` is a folder (rmtree before replacing), `with_export_suffix` handles both suffixes; `ExportResult.onnx_path` holds the model path for either format. `numpy<2.4` is pinned because coremltools 9.0 calls `int()` on 1-element arrays, which NumPy 2.4 rejects ("only 0-dimensional arrays can be converted to Python scalars") — found on a real M1; lift the pin only after CoreML export passes with a newer coremltools. Mac packaging: `packaging/defectlab_mac.spec` (BUNDLE, arm64), `build_mac.sh` (ad-hoc sign unless `DEVELOPER_ID`, notarize with `NOTARY_PROFILE`, dmg via hdiutil); the app exe is also the worker (`--train-worker`). Verified on a real M1 (2026-10): app, MPS training, CoreML export, .app/.dmg build + frozen training — see `docs/mac_checklist_tested.md`.
- **Integration test** (`tests/test_integration.py`, slow): runs the worker as a subprocess with stdin kept open (`Popen(stdin=PIPE)`) — the worker treats a closed stdin as "app gone" and stops, so `subprocess.run` without stdin stops training immediately.
- **ONNX export naming** (F6.3): default `<project>_<mode>_<model>_<YYYYMMDD_HHMMSS>.onnx` at export time, user-editable in the save dialog; pattern tokens `{project}{mode}{model}{date}{time}`; sidecar files share the name (`<name>.metadata.json`, `<name>.classes.txt`). Exports are verified by re-running inference in onnxruntime and comparing to PyTorch (box IoU ≥ 0.99). Crop-model metadata includes tile size and overlap.

## Cross-platform (Linux + Windows 10/11 + macOS Apple Silicon — PRD 5.1, 5.2)

- All OS-specific code lives in `defect_inspection/platform_utils.py` (`IS_WINDOWS`, `IS_MAC`); don't scatter `sys.platform` checks.
- **Compute device** (step 21): every model run asks `platform_utils.resolve_device(requested, purpose)` — never leave Ultralytics' `device` empty, because Ultralytics picks CUDA by itself but never MPS. "auto" → `"0"` (CUDA) / `"mps"` / `"cpu"`; an explicit choice wins; purpose `"verify"` (ONNX export check) is always CPU so PyTorch and ONNX Runtime are compared under the same arithmetic. Used by `trainer.train_args` (resolved in the worker), `evaluate.Predictor` (device stored at init), `SamAssistant.load`, `exporter.verify_onnx`, `inference_devices`. `torch_accelerator()` caches the torch probe, and for MPS also runs one tiny tensor op (`_mps_works`): GitHub's macos-14 runners report `mps.is_available()` but every allocation fails with "MPS backend out of memory (MPS allocated: 0 bytes)"; tests set `platform_utils._accelerator_cache` to fake a CUDA/MPS machine. `PYTORCH_ENABLE_MPS_FALLBACK=1` is set in `defect_inspection/__init__.py` (before torch import) and in `worker_environment()` for the training process. GPU entry of the Train tab = `gpu_device_choice()`; FP16 export needs `is_cuda_label`. macOS: fonts Apple SD Gothic Neo first, DataLoader workers 0, `config_dir()` (augment presets) in GenericDataLocation (~/Library/Application Support) while QSettings (window layout, options) is the native plist `~/Library/Preferences/com.defectlab.DefectLab.plist`, `BACKSPACE_DELETES_SELECTION` (no Delete key on Mac keyboards). Shortcut text written into tooltips must go through `image_canvas.native_shortcut` (⌘ on Mac).
- Paths via `pathlib`; must work with spaces and Korean characters (this repo's own path contains a space).
- Never call `cv2.imread`/`cv2.imwrite` directly — they fail on non-ASCII paths on Windows. Use the `platform_utils` wrappers (`np.fromfile` + `cv2.imdecode`, `cv2.imencode` + `tofile`).
- Text files always `encoding="utf-8"`.
- File names: `platform_utils.invalid_filename_reason` / `sanitize_filename_part` (forbidden chars, Windows reserved names like CON/COM1, trailing dot/space) and `path_too_long` (260).
- Training worker: QProcess runs `sys.executable -m defect_inspection.worker`; every entry point needs an `if __name__ == "__main__":` guard (Windows spawn). Stop = graceful signal, then `kill()` on timeout. Keep DataLoader workers low on Windows.
- CI runs pytest + `--self-check` on `ubuntu-latest`, `windows-latest` and `macos-14` (Apple Silicon; its virtual MPS fails the `_mps_works` probe → CPU only) with `QT_QPA_PLATFORM=offscreen`. The test suite and `docs/mac_checklist.md` were run on a real M1 (results in `docs/mac_checklist_tested.md`).
